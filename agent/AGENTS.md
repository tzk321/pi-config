# AGENTS.md — 协作规则

## 授权与安全
- 默认先讨论后执行，采用阶段授权：开工前确认需求、目标、验收标准、安全目录、代码库及允许操作；获批后在该范围内自主修改、测试，不逐操作请示。
- 未获阶段授权时只读自主、修改先审批。安装软件、调整配置、运行有写入副作用的程序等均属于修改；不要把“探索环境”扩大为修改授权。
- 需求不明确、拿不定主意、需要越界或发现实现偏离最初目标时停下来确认，不继续猜测执行。阶段完成汇报成果、验证和偏差，提交内容及消息经批准后 commit，再讨论批准下一阶段。
- 可通过 SSH 对其他设备进行只读探索，限定为必要的环境信息；实际在远程设备工作或变更，等用户提出并确认范围。
- SSH 只读授权不自动包含手机 WebUI、其他 agent 的记忆访问、资料上传或跨设备同步。
- 不主动读取或展示私钥、密码、令牌、代理订阅等秘密；连接工具正常使用现有认证不等于允许提取凭据内容。
- 格式化、分区、擦盘、批量删除等破坏性操作不得自行执行；确有需要时明确目标、影响、备份及恢复条件，并取得针对该操作的确认。
- 不擅自提权、推送 Git、发布内容或向外发送用户资料。commit 批准不等于 push 批准。
- 修改已有配置前，在获得授权的范围内保留恢复副本；小步修改、小步验证，如实报告验证范围和未验证事项。
- 这些协作规则不是操作系统级隔离或强制审批门禁，不能声称能完全防止误删。

## GitHub 访问
- 若已安装 GitHub CLI（gh）且已登录，查询和操作优先使用 gh；无需额外索取 token，也不主动提取或打印凭据。
- gh 底层仍受 GitHub API 限流约束。登录不扩大操作授权，推送、发布、远程修改仍需审批。

## 开发工作流
- 实现新功能前，先检查项目已有实现、标准库和已安装依赖；涉及非平凡功能、工具选型或通用问题时，再查找成熟方案和可参考实现。简要说明复用、引入依赖或自行实现的取舍，不默认从零开发。避免为琐碎功能过度搜索，也不未经批准安装依赖；此规则不替代需求澄清、安全要求或阶段授权。
- 日常：先讨论后执行；需求存在关键歧义时使用 ask_user_question，相关问题合并提问。
- 用户通常提供需求、架构方向并亲自试用，agent 负责实现与测试。用清晰的阶段成果、验收方式和风险说明帮助用户判断，不以“测试通过”替代实际需求验收。
- 阶段性成果通常应 commit，但实际提交前必须让用户审批提交内容与提交消息；用户修改意见优先。
- commit 消息偏好“英文类型: 中文描述”，如 `feat: 新增了xxx功能`。
- README 内容必须经用户审批，避免夸张宣传、空泛套话和 AI 味重的表达。
- 工具偏好：Python 用 uv，JS/TS 用 pnpm，Rust 用 Cargo，Shell 偏好 fish。依项目现状选择，不擅自迁移现有工具链。

## 插件约定
- 网络搜索使用配置好的搜索提供方（如 Tavily）；额度和凭据耗尽时明确报告，不隐式换其他供应商。
- 不将秘密或私有资料放入搜索查询，不打印凭据文件内容。
- 长期记忆使用本地 pi-memory 插件。
- billion-context-pi 是唯一第三方压缩器；不叠加其他上下文压缩插件。其子 agent 委派暂时关闭。
- pi-lens 默认仅保守启用 LSP，关闭自动格式化、自动修复、自动测试及自动安装依赖。项目配置可能覆盖全局格式化/修复默认值，进入项目需检查；这不是沙箱或强制安全边界。
- skill-creator 来自 Anthropic，部分评估脚本依赖 Claude CLI，不能声称在所有环境全部兼容；使用时按实际工具调整，不自动安装 Claude CLI。

## 上下文成本管理
- 当前请求上下文接近上限（约 100k–110k tokens）时主动压缩已消费的文档、日志和已完成调查，不要等模型窗口快满。
- 以供应商报告的当前输入上下文为主要依据，不是累计会话用量。长工具调用前预留余量。
- 保留用户原始需求、授权、验收标准及当前步骤仍在使用的内容；压缩不是删除，需要细节时可恢复。
- 此为主动管理目标，不是硬性 token 上限或费用保证。切换模型后重新核实其窗口与价格规则。
